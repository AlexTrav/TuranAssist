# Тестовые вопросы для ручной проверки бота

Набор для быстрой проверки TuranAssist вручную – на сайте
(https://alextrav.github.io/TuranAssist/chat) или в Telegram ([@turan_assist_bot](https://t.me/turan_assist_bot)).
Это не обучающие и не исследовательские данные (они в `data/phrases`), а «витрина»: типичные вопросы,
которые стоит задать при демонстрации, и известные слабые места.

| Файл | Что внутри |
|---|---|
| `questions.csv` | 62 одиночных вопроса: ожидаемая тема (`expect`; `ood` – бот должен ответить «не понял»; `clarify:тема1\|тема2` – бот просит уточнить и предлагает эти темы), программа для вопросов о цене, пометка автопроверки (`check`) и комментарий |
| `dialogs.md` | 4 диалога с уточнениями («а в магистратуре?») – контекст проверяется только вручную |

Группы вопросов (`kind`): обычные по всем группам тем, цена конкретной программы, короткие запросы
из одного слова («Гранты», «ЕНТ»), казахский, английский, опечатки и сленг, общение, вопросы не по теме и известные ограничения.

## Автопроверка

Вопросы с `check = yes` прогоняются через сервис тем же кодом, что отвечает пользователям,
в автотесте бэкенда `backend/tests/test_data_test.py` (запускается в CI):

```bash
cd backend && make test
```

Ожидаемые темы взяты из ответов модели и проверены вручную. `check = no` – вопросы, уверенность
по которым близка к порогу 0,577 (результат int8-модели немного зависит от процессора), и известные
ограничения: на них бот сейчас ошибается или честно отвечает «не понял» с подсказками. Такие вопросы
оставлены специально – они показывают, где бот слабее всего:

- короткие запросы, где темы вместе не набирают порог («Документы» – 0,51) или кроме одной темы
  модель видит только «привет» и «спасибо» («Price»): бот отвечает «не понял», но подсказки верные;
- транслит («skolko stoit obuchenie»);
- часть вопросов не по теме, похожих на вопросы о датах («Какая погода завтра?»).
