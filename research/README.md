# TuranAssist – исследование (Задание 2)

Воспроизводимые замеры и рисунки для исследования «Классические и трансформерные методы
классификации намерений для многоязычного чат-бота университета в условиях ограниченных
ресурсов реального времени». Всё запускается в Docker.

```bash
make collect          # оценка сервиса той же моделью и кодом: наборы, ошибки, уверенность, контекст, задержки
make collect-latency  # задержки модели при 1, 0,5 и 0,1 CPU (как на бесплатном Render)
make render           # задержки развёрнутого сервиса на Render (около 4 минут из-за rate limit)
make figures FIGURES=/путь/к/папке   # рисунки по model/reports и research/results
```

| Файл | Что внутри |
|---|---|
| `collect.py` | прогон тестовых наборов через `answer_question` (как отвечает пользователям), доли верных ответов с 95% ДИ Уилсона по стилям и языкам, частые путаницы тем, распределение уверенности, сравнение правил контекста на сценариях и `data/phrases/followups.yaml`, задержки и память |
| `render_latency.py` | три нагрузочных теста `/api/benchmark` на Render и время ответа `/api/chat` с учётом сети |
| `figures.py` | рисунки 1–9 отчёта (matplotlib, шрифт Times New Roman, десятичная запятая) |
| `results/` | сохранённые результаты замеров 09.10.2026 – по ним построены рисунки и таблицы отчёта |

Метрики выбора модели (baseline, трансформер, ансамбль, кривая порога) берутся из `model/reports` –
они получены при обучении, тестовые наборы в выборе не участвовали. `collect.py` оценивает уже
работающий сервис: его цифры на ~1 п.п. отличаются от протокола выбора, потому что эмбеддинги
при выборе считались в Colab, а здесь – локальным ONNX Runtime (результаты int8 немного зависят
от процессора), и потому что сервис добавляет правило суммы тем стоимости.
