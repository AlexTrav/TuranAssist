# Краткое summary проекта

## Задача

По [ТЗ](ТЗ.md) нужно было сделать чат-бот с NLP для заданной области: сбор текстовых данных →
предобработка (токенизация, лемматизация, стоп-слова) → модель на BoW, TF-IDF и/или трансформерах →
интеграция в Telegram или веб → тестирование на реальных сценариях общения.

## Тема и данные

Выбран **ассистент абитуриента и студента Университета «Туран»**: вопросы о поступлении, стоимости,
грантах, учебном процессе, общежитии и документах на русском, казахском и английском. Данные для
обучения – с официального сайта, а не опросы: так ответы проверяемы и привязаны к первоисточнику.

- **Сбор** (`data/collect`): 47 страниц turan.edu.kz и 9 нормативных документов (правила приёма,
  академическая политика, календари) на трёх языках. Сайт на Inertia.js – контент берётся из JSON
  в атрибуте `data-page`, PDF читается по координатам слов, чтобы строки таблиц не разрывались.
  Персональные данные (таблицы с ФИО, списки претендентов на гранты) отфильтрованы.
- **База ответов** (`data/knowledge`): 53 темы в 8 группах, проверенный ответ на трёх языках и
  ссылка на источник у каждой. Бот не генерирует текст – выдуманных фактов о вузе не бывает.
- **Наборы фраз** (`data/phrases`): 1166 обучающих фраз (22 на тему), тест разными стилями
  (опечатки, сленг, транслит, длинные вопросы), 209 вопросов из FAQ других вузов, 155 вопросов
  не по теме и 13 диалогов-сценариев. Проверка данных – `make check` в CI.

## Модель

- **Baseline** (`model/baseline`): 7 конфигураций BoW и TF-IDF с логистической регрессией.
  Лемматизация и стоп-слова дают словесным моделям 1–3 п.п., а лучший – TF-IDF по символьным
  n-граммам (0,805 top-1): устойчив к опечаткам и казахской морфологии без лемматизатора.
- **Трансформер** (Colab): `multilingual-e5-small` – замороженные эмбеддинги + логистическая
  регрессия точнее полного дообучения (CV 0,803 против 0,749: 22 фраз на тему мало для дообучения).
  Энкодер квантизован в ONNX int8 – fp32 не помещается в 512 МБ бесплатного сервера.
- **Продакшн** (`model/ensemble`): ансамбль `0,8 × e5 + 0,2 × TF-IDF char` с порогом уверенности 0,577;
  ниже порога бот честно отвечает «не понял» и предлагает три вероятные темы. Модель выбиралась по
  кросс-валидации и валидационной половине вопросов не по теме, тестовые наборы в выборе не участвовали.

| С порогом «не понял», 95% ДИ Уилсона | TF-IDF char | Ансамбль |
|---|---|---|
| Тест разными стилями | 0,698 | **0,755** [0,705; 0,799] |
| FAQ других вузов | 0,636 | **0,670** |
| Сценарии диалогов | 0,831 | **0,877** |
| Вопросы не по теме отклонены | **0,808** | 0,692 |

Без порога ансамбль угадывает тему в 91% вопросов теста – разница с 75,5% и есть цена честного
«не понял» на сомнительных вопросах.

## Сверх ТЗ: ещё два NLP-компонента

- **Извлечение сущностей**: 32 образовательные программы по словарю сокращений и основ слов
  («ВТиПО», «программист», «юрист», «есептеу техника»). На вопрос «Сколько стоит ВТиПО?» бот отвечает
  ценой именно этой программы; цены генерируются из страницы сайта (`make tuition`) с проверкой полноты.
- **Контекст диалога**: уточнения «а в магистратуре?», «ал магистратурада?», «and for a master's?»
  классифицируются вместе с предыдущим вопросом. Простые правила склеивания ухудшали сценарии
  (вопросы не по теме прилипали к прошлой теме), итоговое правило поднимает уточнения с 4/17 до 14/17,
  не трогая остальные реплики (57/65 на сценариях до и после).

## Бэкенд и Telegram-бот

FastAPI (`backend/`): модель грузится один раз при старте, `/api/chat` возвращает ответ, тему,
уверенность, подсказки, цены программы и разбор вопроса по ступеням конвейера для веб-интерфейса.
Telegram-бот работает в том же сервисе через webhook с проверкой секрета: ответ на языке вопроса,
темы кнопками, уточнения. Rate limit по IP (30 в минуту) и по чату Telegram (20 в минуту), CORS
только для своих доменов, текст вопросов не пишется в логи.

**Реальное время на слабом сервере.** Токенизатор XLM-R переписан на исходной модели SentencePiece:
~20 МБ вместо ~281 МБ у `tokenizer.json`, идентификаторы совпадают на всех 1919 фразах проекта.
Итог – около 320 МБ на контейнер из 512, медиана ответа модели ~6–8 мс. Метрики (p50/p95/p99,
гистограмма, доля ответов быстрее 100 мс, память контейнера) считаются в памяти процесса и видны
на сайте вживую; нагрузочный тест по кнопке прогоняет 100 фраз через модель.

## Фронтенд

Vue 3 + TypeScript + Tailwind CSS 4 в цветах и шрифтах сайта университета (палитра снята с CSS
turan.edu.kz), интерфейс на трёх языках, светлая и тёмная тема, вёрстка от 360 px:

- **главная** – живой разбор вопроса на настоящих данных модели;
- **чат** – темы в боковой панели, цены таблицей, панель «Как бот понял вопрос» (язык, леммы,
  стоп-слова, подслова трансформера, вероятности тем от e5 и TF-IDF, порог, сработавшее правило),
  «Также спрашивают», оценка ответа 👍/👎;
- **калькулятор стоимости** – уровень, программа, форма обучения и отделение, цена за год и весь срок;
- **база знаний** – все 53 ответа с поиском;
- **производительность** – живые метрики и нагрузочный тест;
- **о проекте** – конвейер, сравнение моделей с доверительными интервалами, ограничения.

## Инфраструктура и деплой

Всё запускается в Docker (локальные Python и Node не нужны), `make up` поднимает стек с healthcheck
и ограничениями как на Render (512 МБ, 0,5 CPU). CI на GitHub Actions теми же `make`-командами проверяет
данные, гоняет 148 тестов pytest и 23 теста Vitest и собирает фронтенд. Фронтенд – GitHub Pages,
бэкенд – Render (Docker, бесплатный тариф, описан в `render.yaml`), энкодер e5 хранится на Hugging Face
с фиксированным коммитом и проверкой SHA-256.

## Ограничения

- Транслит («skolko stoit») и опечатки в названиях программ распознаются хуже остального.
- Часть вопросов не по теме уходит в похожие темы (около 31% при выбранном пороге); уточнение без
  союза («Когда подавать заявление?» после вопроса о гранте) не связывается с прошлой темой.
- Казахские и английские тексты не вычитаны носителем языка; данные актуальны на октябрь 2026.
- Бесплатный сервер засыпает после 15 минут простоя – первый ответ после паузы занимает до минуты.
