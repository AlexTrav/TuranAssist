# TuranAssist – бэкенд

FastAPI-сервис чат-бота: по вопросу определяет интент ансамблем моделей и отдаёт проверенный
ответ из базы (`data/knowledge`) на языке вопроса, со ссылкой на первоисточник на turan.edu.kz.
Если уверенность ниже порога, честно отвечает «не понял» и предлагает 3 вероятные темы.

## Запуск

Только в Docker (контекст сборки – корень репозитория):

```bash
make test    # автотесты pytest внутри образа
make run     # http://localhost:8000, документация API – /docs; ограничение памяти 512 МБ, как на Render
make stop
```

При сборке образа энкодер e5 и токенизатор скачиваются с Hugging Face с зафиксированных коммитов
и проверяются по SHA-256 (`app/nlp/model_files.py`).

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/chat` | `{"text": "...", "lang": "ru"\|"kk"\|"en", "context": {...}}` (lang и context необязательны) – ответ, интент, уверенность, подсказки, найденные программы, контекст для следующего вопроса, время обработки |
| GET | `/api/answer/{intent}?lang=` | ответ по конкретной теме – для кнопок-подсказок веб-чата |
| GET | `/api/intents` | 8 групп и 53 интента с названиями на трёх языках |
| GET | `/api/model-info` | сводка качества: TF-IDF, e5 и выбранный ансамбль (с порогом, 95% ДИ) |
| GET | `/api/metrics` | живые метрики: задержки p50/p95/p99 (всего, модель, TF-IDF, e5), запросы, доля распознанных, память, время загрузки модели |
| GET | `/api/health` | проверка живости (healthcheck, «пробуждение» на Render) |

Язык ответа: параметр `lang`, а если он не задан – по тексту вопроса (казахские буквы – kk,
латиница – en, иначе ru).

## Telegram-бот

Работает в том же сервисе и пользуется тем же ансамблем, базой ответов и метриками, что и веб-чат.

- Вопрос своими словами – ответ на языке вопроса со ссылкой «Подробнее»; не понял – 3 кнопки с темами.
- `/start` – приветствие, `/topics` – темы кнопками (группа → вопрос → ответ), `/help` – справка.
- Отвечает на языке вопроса; `/lang` закрепляет язык ответов или возвращает режим «Как в вопросе».
- Имя, описания, меню команд и аватар задаются `make bot-profile` на трёх языках; меню показывается
  на языке Telegram пользователя.
- Понимает уточнения: после «Сколько стоит ВТиПО?» можно спросить «а в магистратуре?»; тема чата
  хранится в памяти 10 минут.
- Лимит – 20 сообщений в минуту на чат (запросы приходят с IP Telegram, лимит по IP здесь не работает).

Настройка – `backend/.env` (шаблон `.env.example`, сам `.env` в git не попадает):

```bash
make bot-dev   # локально: бот опрашивает Telegram (long polling), публичный адрес не нужен
make webhook   # после деплоя: регистрирует webhook https://<бэкенд>/telegram/webhook и меню команд
```

В продакшне Telegram присылает обновления на `POST /telegram/webhook`; запрос принимается только
с секретом из заголовка `X-Telegram-Bot-Api-Secret-Token`. Без `TELEGRAM_BOT_TOKEN` бот выключен.

```
  knowledge.py      – база ответов и ссылки на источники из манифеста корпуса
  tuition.py        – цена по конкретной программе из data/knowledge/tuition.yaml
  schemas.py        – схемы запросов и ответов
  service.py        – общая логика «вопрос -> ответ» для веб-чата и бота
  bot/
    handlers.py     – команды, вопросы, кнопки, лимит на чат
    telegram_api.py – тонкий клиент Bot API на httpx
    webhook.py      – эндпоинт webhook с проверкой секрета
    polling.py      – long polling для локальной разработки
    setup_webhook.py – регистрация webhook и меню команд
    texts.py        – тексты бота на ru/kk/en
  nlp/
    classifier.py   – ансамбль: 0,8 × e5 (ONNX int8 + голова логрегрессии) + 0,2 × TF-IDF char

    preprocess.py   – предобработка текста (общая с обучением в model/)
    language.py     – определение языка вопроса
    entities.py     – извлечение сущностей (программ) по словарю псевдонимов
    context.py      – правило контекста диалога для уточнений («а в магистратуре?»)
    model_files.py  – загрузка моделей с HF и проверка SHA-256
  metrics/
    collector.py    – задержки последних 1000 запросов и счётчики в памяти
  security/
    rate_limit.py   – slowapi, IP из X-Forwarded-For

```

## Цена по программе

Второй NLP-компонент после классификатора – извлечение сущностей. Модель определяет тему вопроса
(«стоимость бакалавриата»), словарь из data/knowledge/programs.yaml – программу («ВТиПО»).
Если и то и другое найдено, ответ – цены именно этой программы по формам обучения на языке вопроса.

На коротких вопросах вроде «ВТиПО сколько стоит» модель делит вероятность между интентами
«стоимость бакалавриата» (0,49) и «стоимость магистратуры» (0,26) и не проходит порог 0,58.
Если в вопросе есть программа, с тем же порогом сравнивается их сумма (0,75) – вопрос
распознаётся. Без программы правило не работает, новых настраиваемых чисел оно не вводит.

Не распознаются пока опечатки в названии («психалогия») и одно название без вопроса («ВТиПО»):
бот отвечает «не понял» и предлагает темы.

## Контекст диалога

Уточнения вроде «а в магистратуре?», «а PhD?», «ал магистратурада?», «and for a master's?» сами по
себе бессмысленны или понимаются неверно («а в магистратуре?» – «программы магистратуры»).
Поэтому уточнение классифицируется вместе с предыдущим вопросом: «Сколько стоит ВТиПО? а в магистратуре?»
– стоимость магистратуры по ВТиПО.

Простые правила проверены и отвергнуты: «склеивать, если бот не понял», «если реплика начинается
с союза», «если склеенный вариант увереннее» снижали точность на диалогах-сценариях с 57/65 до 49–54/65 –
вопросы не по теме («Какой курс евро?», «Где столовая?») прилипали к прошлой теме вместо честного
«не понял». Сценарии использовались для отбора правила, поэтому как независимая оценка они здесь
уже не годятся – их задача показать, что правило ничего не сломало. Итоговое правило (pp/nlp/context.py):
склеенный вариант принимается, только если реплика начинается с союза-уточнения («а», «и», «ал»,
«and», «what about») и либо без контекста не понята, либо короткая (до 5 слов) и остаётся в той же
группе тем.

| Набор | Без контекста | С контекстом |
|---|---|---|
| 13 диалогов-сценариев (65 реплик) | 57/65 | 57/65 |
| 17 пар «вопрос – уточнение» (13 уточнений, 4 смены темы) | 4/17 | 14/17 |

Ограничения: уточнение без союза («Когда подавать заявление?» после вопроса о гранте) не
связывается с прошлой темой; вопрос не по теме, начатый с «а» («а курс евро какой?»), может
прилипнуть к прошлой теме.

Сервер контекст не хранит: в ответе /api/chat приходит context (вопрос и тема), веб-чат
присылает его со следующим вопросом и держит только в памяти вкладки. Бот хранит тему чата
в памяти процесса 10 минут. Язык уточнения определяется по всему диалогу.

## Решения и ограничения

- **Память.** Сервис должен помещаться в 512 МБ бесплатного Render. Токенизатор из `tokenizer.json`
  (библиотека `tokenizers`) занимал ~280 МБ, поэтому токенизация реализована на исходной модели
  SentencePiece (~20 МБ) – идентификаторы совпадают с эталонными на всех 1919 фразах проекта.
  Итог: ~295 МБ на контейнер, загрузка модели ~4 с, ответ ~6 мс (при 0,5 CPU).
- **Rate limit** – 30 запросов в минуту на IP. Проверка вопроса вызывается внутри эндпоинта, а не
  через `Depends()`: иначе отклонённые запросы не попадали бы в счётчик slowapi (покрыто тестом).
- **CORS** – только dev-сервер Vite, контейнер фронтенда и `https://alextrav.github.io`.
- **Логи** – интент, уверенность, язык и время обработки; текст вопроса не пишется – в нём могут быть
  персональные данные.
- **Метрики** хранятся в памяти процесса и обнуляются при перезапуске (на Render – после сна).
  Полноценный Prometheus/Grafana для учебного сервиса на одном инстансе избыточен.
- **Слабые места модели** – транслит и часть вопросов вне базы, похожих на темы университета
  (например, «Какая погода завтра?» уходит в академический календарь). Подробности – в `model/README.md`.
